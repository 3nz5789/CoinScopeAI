# Phase 4 Backlog — Later-Stage Expansion, Sales, Partnerships, Fundraising, Scenarios, Scaling Readiness

## Phase 4 scope

**Gated expansion.** Phase 4 work is **explicitly contingent** on Phase 3 exit. None of these tasks should be worked in parallel with earlier phases unless the dependency table in `18-roadmap/dependency-map.md` says they may. The phase emphasizes preparing — not committing to — the work that opens up only after monetization, trust, and operational discipline are validated.

**Time horizon:** beyond 90 days from today; tied to the canonical phase map (P3 → P5) more than to calendar dates.

**Phase exit criteria (long-horizon):**

- Desk Preview SKU activated post P2 stabilization.
- Compliance posture upgrade scoped + initiated.
- Desk Full v2 launch readiness criteria visible (per-seat features, audit-grade exports).
- Scenario models v1 published (best/base/worst).
- Fundraising posture (bootstrap vs venture) decided with rationale.

**This phase is gated.** Pulling any item forward without its dependency complete is the single most likely way the framework collapses.

**This is a deliberately gated sequence.** Each section's dependency must be live before the section starts. There is no version of this phase that runs all sections in parallel.

## Phase 4 exit gate (long-horizon)

Phase 4 is "complete" when CoinScopeAI is at P5 and:

- [ ] Desk Preview activated and tier mix is healthy.
- [ ] Compliance posture upgrade scope locked and counsel retained.
- [ ] Audit-grade exports + role-based access scaffolding scoped.
- [ ] Desk Full v2 sales motion documented with first 5 prospects identified.
- [ ] Per-seat rate locked.
- [ ] Scenario models v1 published.
- [ ] Fundraising posture decided with rationale.
- [ ] First FT hire role profile defined; equity posture established.
- [ ] Operating cadence audited for team scale.
- [ ] Infrastructure scaling readiness assessed.

**Forward-only rule:** if any Phase 4 item is being pulled forward to chase revenue, an advisor input, or external pressure, the dependency map must be re-walked first. Pulling forward without checking dependencies is the failure mode this phase backlog exists to prevent.
