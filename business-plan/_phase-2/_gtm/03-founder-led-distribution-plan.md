## 1. The plan in one paragraph

Founder spends 5–10 hours per week on GTM at P1 Narrow Ship — alongside ~3 hours/coverage day on support (per `_support/01` §3) and the remaining time on product + strategy. GTM time is allocated to weekly long-form writing on owned channels (blog + LinkedIn), targeted founder direct outreach to Karim / Layla profiles, validation-cohort + founder-cohort comms, and methodology-doc maintenance. No paid acquisition. No daily short-form. No live streams. No memes. The cadence is methodical because the brand is methodical.

## 4. Content rotation

Long-form content rotates across four types. Each type has explicit register + audit rules.

### Type A — Methodology pieces

**Cadence:** ~1 per month
**Register:** product-tier — technical, terse, declarative, data-led
**Length:** 1500–3000 words
**Audience:** Karim primarily; Omar reads post-signup; Layla reads as credibility check
**Examples of topics:**
- "How the regime classifier produces Trending / Mean-Reverting / Volatile / Quiet labels"
- "The risk gate logic: why we reject more trades than we accept"
- "Backtest discipline at CoinScopeAI: what we test, what we don't, why"
- "PCC v2 §8 Capital Cap explained — the gates between testnet and live"

**Anti-overclaim audit:** every claim links to engine source / methodology page / decision-log entry.

### Type B — Case-study / cohort-feedback pieces

**Cadence:** ~1 per month (more frequent during P0 validation cohort)
**Register:** product-tier
**Length:** 1000–2000 words
**Audience:** All three personas; trust-signal piece
**Examples of topics:**
- "What we learned from the P0 validation cohort — gate-rejection patterns, regime-flip behaviors"
- "Cohort-N retention: who stayed on Trader, who upgraded to Desk Preview, what changed their decision"
- "Sub-$5k disciplined cohort behavior over 12 months: what 'we'll be back' looks like in data"

**Anti-overclaim audit:** all cohort data anonymized; no persona-identifying details; statistical claims have falsification range.

### Type C — Process / decision-log pieces

**Cadence:** ~1 per month
**Register:** product-tier with founder voice
**Length:** 800–1500 words
**Audience:** All three personas + Phase 4 fundraising audience (later)
**Examples of topics:**
- "Why we won't run paid acquisition in 2026"
- "The decision to lock leverage at 10x (PCC v2 §8 §8 Capital Cap)"
- "How we picked Track B: $79 / $399 / $1,199 + per-seat $149 / $249"
- "Validation phase: 30 days, 40-cohort cap, what we'll publish"

**Anti-overclaim audit:** decision-log cross-reference required; no claims about future revenue / customer counts.

### Type D — "What we don't do" pieces

**Cadence:** ~1 every 6–8 weeks
**Register:** product-tier
**Length:** 500–1500 words
**Audience:** Anti-ICP filter + trust-signal for Karim + Layla
**Examples of topics:**
- "We don't generate signals for non-futures markets, and here's why"
- "Why we won't add a Trader Lite tier"
- "We declined to integrate with [signal-group product] — here's the reasoning"
- "We don't custody funds — what that means and why we never will"

**Anti-overclaim audit:** decline-reasoning grounded in §5.3.3 packaging principles + Phase 1 anti-claim list.

### Rotation pattern (12-week cycle)

| Week | Content type |
|---|---|
| 1 | Type A — Methodology |
| 2 | Type C — Process / decision-log |
| 3 | Type B — Case-study |
| 4 | Type A — Methodology |
| 5 | Type D — What we don't do |
| 6 | Type C — Process / decision-log |
| 7 | Type A — Methodology |
| 8 | Type B — Case-study |
| 9 | Type C — Process / decision-log |
| 10 | Type A — Methodology |
| 11 | Type B — Case-study |
| 12 | Type D — What we don't do |

12-week cycle = 4 Type A + 3 Type B + 3 Type C + 2 Type D. Front-loads methodology + case-study (high trust-load) over decision-log + decline pieces.

## 5. Founder direct outreach protocol

Direct outreach is the second-most-important GTM motion at v1 (after content). Specifically targets Karim + Layla profiles where personalization is feasible.

### Targeting

**Karim profiles** (Engineer Trader):
- Quant trading communities (QuantConnect contributors, vectorbt PRO users)
- Technical writing on Substack / Medium about crypto-trading systems
- Open-source crypto-trading library contributors
- Engineers writing about backtest discipline / risk-gate logic publicly

**Layla profiles** (Solo PM):
- Solo PMs visible in financial-services forums + LinkedIn
- People writing publicly about managing $200k–$1M aggregate books
- Adjacent: micro-fund founders on the small end (sub-$5M AUM)
- Adjacent: ex-buy-side professionals who run own books post-departure

**Off-limits for direct outreach:**
- Anyone visibly aligned with anti-ICP (signal-group operators, copy-trade promoters, leverage-maximizer influencers)
- Casual-retail traders with high social-media performance (anti-persona per §3.5)
- Anyone in US jurisdiction (per memory `project_jurisdictional`)

### Message form

Direct outreach messages follow this structure:

```
Subject: [Specific hook from their public writing/content]

[Hi {{first_name}},]

[1-2 sentences specific to their work — quote a paragraph from their writing 
or reference a specific point they made.]

[1-2 sentences on what we built: "I've been building CoinScopeAI — 
a capital-preservation-first AI-driven crypto futures system for 
{{disciplined traders / Solo PMs running close-circle books}}. Currently 
in 30-day validation phase, testnet only, no real capital."]

[1-2 sentences on the connection: "Saw your {{specific writing topic}} 
and thought it overlapped with how we think about {{specific framework / 
methodology aspect}}. Curious if you'd want to {{read the methodology 
docs / try Free / chat about how it works}}."]

[Soft CTA: "If not relevant, no worries. Methodology page is {{link}} 
if you want to skim."]

— Mohammed
```

### Volume

- 3–5 outreach messages per week
- ~1 follow-up per week to prior outreach (max 1 follow-up; if no response after 2 messages, drop)
- Track in Notion or similar; volumes feed KPI dashboard

### Anti-pattern guards

- **No mass outreach.** Each message is specific; copy-paste is forbidden.
- **No "free Trader for a month" offers in outreach.** Per `_pricing/04-trial-and-intro-offer-options.md` Pr2-3 — no free trial. Founder-cohort is the only intro offer.
- **No prospect aggressive follow-up.** Max 1 follow-up; then drop.
- **No outreach that drifts from product-tier register.** Even on LinkedIn, the register stays product-tier.
- **No outreach to anti-ICP profiles.** Founder reviews target list quarterly; removes drift.

## 6. Cohort-direct comms

Two cohorts get founder-direct comms during P1 Narrow Ship: validation cohort (P0, cap 40) and founder-cohort window (60 days post-public-launch).

### Validation cohort (P0)

- **Channel:** Private Telegram group (cohort-only) + email (per Su-6)
- **Cadence:** 2x weekly during validation phase (1 status update + 1 cohort-feedback request)
- **Content:** Engine update notes, gate-rejection statistics, regime-classifier behavior in current market, cohort feedback prompts
- **Founder time:** ~30 min/week
- **Anti-pattern:** Don't use cohort comms for marketing pitch. Cohort is for validation; sales conversion is post-cohort.

### Founder-cohort window (60 days post-public-launch)

- **Channel:** Email (founder-cohort window opt-in subscribers + new signups during window)
- **Cadence:** Pre-launch (T-7 to T-0): waitlist warming. Window-open (T+0 to T+60): weekly window updates with explicit time remaining. Window-close (T+60): expiration notification.
- **Content:** Founder-cohort eligibility, time remaining, canonical phrasing, conversion CTA
- **Founder time:** ~1 hr/week during window; ~30 min/week post-window for new-signup standard onboarding
- **Anti-pattern:** Per §6.10 Flag 1 — never "lifetime / forever / always / locked-in." Single canonical phrasing per `_pricing/03` §6.

## 10. Anti-patterns specific to founder-led motion

- **Daily posting compulsion.** Anti-methodical per BRAND. Resist the social-media engagement-loop trap.
- **Engagement-bait writing.** "What's the worst trading mistake you've made?" — drives engagement, attracts adverse selection. Skip.
- **Twitter / X opening at v1.** CANDIDATE-P3 only; opening it at v1 fragments founder time + risks register drift.
- **Founder-personality cult.** "Mohammed says..." framing. Founder is the operator, not the brand. Brand is CoinScopeAI; founder voice is one surface.
- **Replying to crypto-Twitter beefs.** Adjacent context = anti-ICP exposure.
- **Gating methodology behind email signup.** Methodology is public per §5.3.1. Gating it is overclaim friction.
- **Promising upcoming features in outreach.** Roadmap features need v2 / v3 qualifier (per `_support/05` §5 anti-overclaim checklist). "We're working on X" is risky outside qualified roadmap surfaces.
- **Mass-outreach.** 50 cold messages with the same body. Single-shot direct outreach only.
- **Founder support load → GTM time bleed.** When support spikes, GTM doesn't borrow back from product. Per `_support/01` §6 — support takes priority during incident; GTM cadence pauses.
- **Discount appeals in outreach.** "Try Trader at 25% off this week only." No urgency mechanics. Founder-cohort is the only time-bounded offer; available equally to all signups in window.
