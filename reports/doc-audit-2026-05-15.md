## 6. New Features / Changes This Week (2026-05-12 – 2026-05-15)

Based on code reviews from 2026-05-13 and 2026-05-15, the following modules are new or substantially changed this week and are **not yet documented**:

### 6a. `scanner/` v2 Package (New — not documented anywhere)

A new canonical scanner package was introduced with a clean async architecture:

| Module | What it does |
|---|---|
| `scanner/base_scanner.py` | `BaseScanner` ABC — `async scan(symbol) -> ScannerResult` |
| `scanner/volume_scanner.py` | Volume ratio vs rolling avg + taker buy imbalance; threshold 3.0× |
| `scanner/liquidation_scanner.py` | WebSocket-fed liquidation buffer + dominance ratio |
| `scanner/orderbook_scanner.py` | Bid/ask imbalance scanner; `IMBALANCE_THRESHOLD = 0.65` (hardcoded) |
| `scanner/pattern_scanner.py` | Candlestick pattern detection |
| `scanner/funding_rate_scanner.py` | Funding rate extremes; absolute + relative + reversal checks |

The legacy `scanners/` package (sync, DataFrame-based) is being phased out. `signal_generator.py` still imports from it — this is a known P1 migration item.

**Should be documented in:** `docs/architecture/system-overview.md` (scanner v2 section), and a note added to `docs/api/engine-api-contract.md` under the `/scan` endpoint.

### 6b. `signals/confluence_scorer.py` (New — not documented)

`ConfluenceScorer` is the new canonical scoring pipeline, replacing the legacy `FixedScorer`. It aggregates hits from all v2 scanners into a unified 0–100 confluence score. Used by `confluence_scorer.py` and `api.py`; not yet wired into `signal_generator.py`.

**Should be documented in:** `docs/architecture/system-overview.md`, scanner section.

### 6c. `alerts/telegram_notifier.py` (New canonical — not documented)

New async Telegram sender with:
- SHA-256 fingerprint deduplication (120-second TTL, prevents duplicate alert storms)
- 3-retry exponential backoff
- HTML parse mode (safer than Markdown for special characters)
- 4096-character chunking for long messages

The legacy `alerts/telegram_alerts.py` (sync, no dedup) is being phased out. `alpha_decay_monitor.py` still uses the legacy one — known P2 migration item.

**Should be documented in:** A new `docs/architecture/alerts.md` or `docs/runbooks/alert-system.md`.

### 6d. `alerts/rate_limiter.py` — Thread-Safety Bug Found

A **data race** was identified in `allow_signal()`: the symbol token refund writes to `_tokens` without holding `bucket._lock`. Under concurrent multi-symbol scans, this can cause incorrect rate limit accounting.

**Status:** Bug identified in 2026-05-13 review. Fix: acquire lock before refund. This is a P1 fix.

**Not yet documented** in any known-issues or changelog entry. Should be added to `CHANGELOG.md` under `[Unreleased]`.

### 6e. `risk/circuit_breaker.py` v2 (New — documented only partially)

Clean async circuit breaker with proper equity-referenced daily loss calculation (vs the old `core/risk_gate.py` which used `initial_capital` as the reference — a semantic error after account growth). The v2 version is the canonical implementation going forward.

**Status:** `core/risk_gate.py` still exists in parallel. Which one is on the hot path needs confirmation before `core/risk_gate.py` can be retired.

### 6f. Binance Testnet URL Update

`binance_rest.py` updated to `demo-fapi.binance.com` (post-April 2026 Binance testnet migration). Confirmed correct in 2026-05-15 review.

**Should be reflected in:** `.env.example` comment and `docs/runbooks/local-development.md` prerequisites.

### 6g. `risk/position_sizer.py` — Kelly Input Validation Gap

Kelly fraction computation (`_kelly_fraction()`) does not validate trade count before computing. With fewer than 20 trades, Kelly outputs are unreliable. Half-Kelly cap of 25% is a safety net but does not prevent near-zero fractions from silent fallthrough.

**Status:** P2 fix identified. Not yet in `CHANGELOG.md`.
